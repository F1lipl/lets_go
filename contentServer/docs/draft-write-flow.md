# 创建与保存草稿

`POST /api/v1/posts` 创建一个尚未发布的 Post 和版本为 1 的草稿；`PUT /api/v1/posts/:postId/draft` 使用 `expectedDraftVersion` 替换整份草稿。省略的标题、封面、话题等字段按空值处理，不是局部补丁。成功保存后草稿版本增加，Post 版本保持不变；发布时再同时检查 Post 与草稿版本。

Handler 限制写入请求体大小并解析参数。Logic 从登录上下文获取作者，将 API 字段转换为领域输入并组装回包。Domain 校验正文结构、块关系、话题、封面参数和帖子生命周期，生成纯文本与图片引用。Repository 用一个数据库事务写入 Post、草稿及其图片引用；保存时按照与发布相同的顺序读取 Post、草稿，草稿行只读取版本而不加载旧正文，再条件更新整份内容和图片引用。引用的图片必须属于作者且未失效；草稿允许图片仍在上传或处理中，发布仍要求图片已就绪。

当前 API 没有创建请求的去重标识。客户端在响应丢失后重发创建请求可能得到两个草稿；这是接口契约仍需单独决定的生产约束，不能靠草稿版本解决。
